# 性能与内存基线（2026-11-07）

以保留现有识别结果、录音时序、取消与续录、渠道回退、窗口动画及设置行为为前提，减少重复排版、分配和资源滞留。

## 实现范围

- 浮窗按请求字体缓存配置，避免把系统的中文回退字体当成字体变化。只替换预览中发生变化的文字区间，保留完整 Unicode、稳定前后缀及原有淡入进度；仅使动画涉及的原生字符范围失效。相同文本及字体复用测量结果。
- 音频分帧仅保留不足 320 样本的尾部，整帧直接形成独立输出；复用重采样输出缓冲。采样率、20ms 帧长、补零和旧录音尾帧归属保持原有规则。
- 预录及千问收包使用先进先出缓冲，避免每次出队都搬移整个数组；已消费的对象立即释放，并逐步收缩峰值后的缓冲存储。取消读取不能消耗下一轮的数据，关闭后仍按顺序排空已缓存的数据。
- 离线引擎复用单个可重设的空闲计时器，替代每个请求新增一次延迟清理任务；停止时取消计时器，关闭管道并释放解析缓冲。空闲退出仍为五分钟。
- 会议豆包识别直接使用会议管线提供的音频流，移除重复的整段内存保留；会议磁盘存档和完整片段回退重放保持不变。普通豆包输入仍保留更换设备后的重试音频。
- 混音器先移出待修改的音频桶，避免数组写时复制；静音帧共享不可变存储。千问 PCM 发送减少中间 Data 复制，会议待处理数量直接计数。

## 同负载对比

两个通用 release 构建使用同一 Swift 优化级别、相同诊断代码和本机 Apple Development 签名。基线为 `099bdf6` 加诊断入口；在同一台 Mac 上交替运行优化前后各三次，表内为三次结果的中位数。测量使用 `/usr/bin/time -l` 及程序生成的 `benchmark.json`。

固定负载包含 30,000 个 512 字节网络包的入队与顺序读取、2,000 次 48kHz 输入转换、30,000 帧双源混音，以及 180 次真实原生浮窗文字更新（最终 6,432 个字符，含生僻字和 emoji，每五次加入一个重复回包）。动画开启，浮窗固定为标准大小；临时设置使用独立 UserDefaults，不访问麦克风、供应商或用户文档。

| 指标 | 优化前 | 优化后 | 降幅 |
|---|---:|---:|---:|
| 浮窗更新 P95 | 51.35 ms | 18.78 ms | 63.4% |
| 浮窗更新 P50 | 21.44 ms | 11.99 ms | 44.1% |
| 主线程心跳间隔 P95 | 47.08 ms | 28.87 ms | 38.7% |
| 网络包队列总耗时 | 1154.02 ms | 630.00 ms | 45.4% |
| 音频转换总耗时 | 23.60 ms | 10.72 ms | 54.6% |
| 双源混音总耗时 | 56.65 ms | 42.63 ms | 24.7% |
| 进程累计 CPU 时间 | 6.56 s | 4.04 s | 38.4% |
| 峰值内存足迹 | 57.63 MiB | 52.89 MiB | 8.2% |
| 最大驻留内存 | 123.81 MiB | 118.78 MiB | 4.1% |

所有六次运行的音频帧数、PCM 校验值、网络包校验值、混音校验值和文字更新数量均一致。结果反映本机固定压力负载的改善，不作为供应商网络延迟、离线模型占用或所有使用场景的固定收益。
