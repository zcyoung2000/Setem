来源：2026-11-04 豆包、微信在流式上屏时缺尾字/缺润色稿的问题；修复前提交 `e024f0725347d89beaf2d3e9b91a34a78618f0b6`。
最初参照上游 `2aaa89dc55e7061138da2be1ac29bc4769dcba19` 的连续输入行为；当前完整输入流程对照 `main@3ba017826eef7fac405198510b03859eb5b6c8c4`，详见 [对齐契约](dictation-parity.md)。

## 需求、约定与风险

- R1：等待上一段定稿时再次长按或点按，应接着录音，保留上一段最终稿。
- R2：旧会话的成功、取消、错误、临时文本及超时回调不能影响新会话的录音、文本或完成状态。
- R3：同一会话按录音顺序合并各段，完整定稿/润色稿优先于临时文本；每段定稿后拒收迟到临时文本。
- R4：显式 Esc 取消、15 秒等待超时、失败保留已识别文字及长按并发送仍有效。
- R5：本地与 CI 自动运行基线，发布构建必须先通过测试。
- R6：临时识别引擎释放时关闭其网络连接；仍有缓存持有的连接可以保持打开。

约定：延续同一会话时固定识别渠道和上屏模式，各段独占识别引擎；录音中的重复开始/停止为幂等操作。某段失败保留其最新临时文本并报告错误，其他段继续完成。发送仅在所有段完成、无错误且文本非空时发生。多渠道候选沿用独立选择流程，再按录音快捷键不再取消候选。

主要风险：完成顺序与录音顺序不同；取消不被供应商任务立即响应；旧超时在继续录音后触发；录音启动失败误清空旧文本；上一段定稿误停当前录音；自动回车早于最终文本。

不变量：旧段不得停掉仍未定稿的新录音，硬件停止由当前会话统一管理；只有当前会话可更新 UI；每段最多定稿一次；完成通知和自动发送每个会话最多一次；继续收音前取消旧等待计时。

## 场景与验证依据

以下矩阵在对应测试代码编写前建立。所有场景均为 P0，使用 XCTest；语音场景使用可控制的录音源/识别响应，连接生命周期场景使用本机回环服务和真实 Foundation/Network 对象。不访问公网，不依赖真实麦克风、辅助功能权限或某个输入框。

| 场景 / 对应测试 | 需求 | Given / When / Then | 验证依据 |
|---|---|---|---|
| `testContinueWhileFinalizingKeepsPolishedTextAndRecording` | R1/R3 | 第一段等待定稿，开始第二段，第一段随后返回润色稿；第二段仍在录音，最终输出两段完整稿 | 精确文本、录音停止次数、完成次数 |
| `testOutOfOrderFinalsRemainInRecordingOrder` | R1/R3 | 后录的段先完成；等待前段后按录音顺序合并 | 完整文本、完成前无提交 |
| `testLatePartialCannotOverwriteFinal` | R2/R3 | 一段已定稿但另一段未完成，旧临时回调到达 | 原定稿不变、尾字完整 |
| `testOldCallbacksCannotStopOrOverwriteNewSession` | R2 | 取消旧会话，开启新会话，再释放旧成功/取消/错误回调 | 新录音继续、无旧文本/错误/完成通知 |
| `testResumeInvalidatesOldTimeout` | R1/R2/R4 | 第一段等待超时计时已开始，继续录音并推进旧计时 | 新录音不停止、无取消事件 |

| `testExplicitCancelFreezesStreamImmediately` | R2/R4 | 录音时取消，再到达临时/最终文本 | 录音仅停一次、一次取消、无后续文本更新 |
| `testFailedSegmentKeepsPartialAndDoesNotStopNextRecording` | R3/R4 | 上一段失败，下一段正在收音 | 当前录音继续、保留两段内容、错误可见、不自动发送 |

| `testImmediateEmptyFinalOrFailureRetainsLastPartial` | R3 | 服务端同步发出最后临时文本后立即返回空定稿或抛错 | 同步回调不被完成事件抢先丢弃、尾字保留 |
| `testStartFailurePreservesPendingSession` | R1/R4 | 上一段待定稿，续录启动失败 | 不丢旧会话/文字、仍能完成或再次续录 |
| `testRepeatedStartAndStopAreIdempotent` | R1/R4 | 录音中重复开始，重复停止 | 仅一份音频、一份引擎、仅停一次 |
| `testSendWaitsForEveryFinalAndRequiresNonemptySuccess` | R3/R4 | 长按并发送，多段乱序定稿/空文本/失败 | 最后完整稿只完成一次，空文本/失败不发送 |
| `testReleasingWebSocketCancelsUnderlyingTask` | R6 | 创建连接后释放包装对象 | 包装对象析构、URLSession 底层任务结束 |
| `testRetainedWebSocketStaysOpenUntilLastOwnerReleasesIt` | R6 | 缓存仍持有连接，再释放最后一个持有者 | 缓存期间任务存活，最后释放后任务结束 |

独立窗口测试 `swift test --filter MeetingPanelTests` 保留原样，不属于语音/音频基线。此前观察到其展开高度/中间帧两条断言失败（窗口一直为 292×82）；本次最新全量 64 个测试和该窗口单独运行均通过。没有修改会议窗口实现或放宽断言，也不将这次通过描述为修复了此前的窗口问题。

手工验收：在目标应用输入框分别使用豆包/微信，开启与关闭「边说边上屏」；说到句尾立即松键，等待定稿后检查尾字；上一段等待时立即继续说第二段；Esc 后马上重新录音；检查长按并发送只发送一次完整文本。自动基线覆盖软件会话流程，目标应用的键盘事件兼容性仍由这组手工步骤验证。

新增 [浮窗状态回归](dictation-hud-regression.md)：松键后收起波形，保留浮窗显示 `thinking` 与加载指示，完整定稿后关闭；迟到临时文本不能覆盖提示。`DictationHUDTests` 使用生产停止及完成入口、真实原生文字/加载控件及渲染位图，覆盖单渠道、长按发送和立即续录，已纳入同一基线入口。
