# 听写静默容灾

2026-11-08，按用户要求：选择一个在线渠道，但连接失败或阶段等待过久时
自动改用另一个在线渠道。保持同一个浮窗，不展示渠道切换提示，最终只
输入一次完整文本。明确改变失败恢复行为，不改变成功转写的拼接、空定稿、
标点及手动停止规则。离线模式不自动上传到在线渠道。

## 现场和触发条件

`Setem` 日志 00:55:21 记录微信连接 TLS `-1200`（底层 `-9816`），连接
经 utun4 隧道；只能确认连接层握手失败，不能据此归咎特定代理或服务端。
原始日志 `/tmp/setem-failover-errors.log`。不会通过关闭证书校验处理此错误。

在线主渠道明确失败时立即尝试备选；收到有声帧后连续4秒无有效文字进展，
或停止收音后2秒仍未定稿，启动下一个在线渠道。微信依次备选豆包、千问；
其他在线渠道按豆包、微信、千问顺序排除自身。每段每个渠道至多一次。
超时触发后保留尚未失败的原任务，先返回健康完整结果的渠道获胜。
取消、麦克风故障及主渠道成功空定稿不触发容灾；备选空结果不允许抢占
已有语音，继续尝试其他渠道。全部在线渠道失败才显示错误。

## 不变量与验证计划（实现前）

- 一份录音源，完整帧归档并回放给后启动的渠道，首音/尾帧及续录段顺序不丢。
- 主渠道的失败不会中断收音。保持原有预览直到备选有文字；旧任务的迟到
  预览不能覆盖当前备选预览。最终文本整体替换，不拼接两个渠道的稿件。
- 所有引擎仍通过池独占借用并等预热；失败、取消或未获胜引擎不归还。
  备选使用独立的完整定稿/快速回放池，不把半段临时稿当作完整成功。
- Esc/会话取消后停止泵、计时和备选；不等待不响应取消的旧厂商回调。
  旧段不能停止新段录音或影响新段的文字、UI和计时。
- 保留15秒会话等待上限。后台只保留本段音频，结束/取消后清理。
- 先用受控失败、计时、完整帧和精确最终文字回归；随后运行完整门禁。
  自动测试不调用公网识别服务或真实麦克风，不宣称实测供应商故障恢复。
